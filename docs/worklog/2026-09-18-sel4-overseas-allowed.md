## 三、货 1 · 把「旁证」拆成两支（代码）

**拆法**：⛔ 不加 `kind` 字段、⛔ 不返回二元组——**直接砍掉 `offtopic_reason`**，换成两个各问一件事的谓词。
理由：只要还留着一个「返回两支之一」的函数，下游就永远只问得出「它旁证吗」，
问不出「它海外吗」；留着它等于把提货单那句「⛔ 不许留一个仍把两支当同一件事的调用点」
交给下一个人去守。砍掉之后**语言本身不让你再把两支揉回去**。

```
is_contrast_source(*, contrast)         # 讲的是别家产品吗 → ⛔ 仍不进关键发现与建议
is_overseas_source(row, *, question)    # 题面只问国内而它来自海外平台吗 → ✅ 放行，但必须标明
```

⚠️ **判定逻辑一个字没变**（还是「题面带 `DOMESTIC_MARKERS`」×「平台在 `OVERSEAS_PLATFORMS`」、
`contrast` 为真即对照）。变的只是**待遇**——这一点写进了两个函数的 docstring，
省得下一个人以为口径翻案顺手改了判法。

### 判域（三处，都是「一条结论」的粒度）

1. 开篇节里的编号关键发现行（与软检 ⒞ 同一份 `summary_findings`）；
2. 「关键发现」节里的每个二级小节（标题 + 正文）；
3. 建议节里的每条编号建议——⚠️ **连降级区一起判**。

⚠️ 第 3 条**故意比建议门禁多管一段**，这是本货最要紧的一个判断：
标明出身跟证据强不强**没有关系**，而实测第三轮真稿里**唯一**一条海外引用（S38）
恰好落在降级区「值得进一步验证的方向」。若沿用 `advice_entries` 默认判域（降级区免检），
整道闸对着真稿一条都量不到 ⇒ **红绿两侧都是 0，什么都没证明**（坑 23′）。
⛔ 没另写一份切法：给 `run.advice_entries` 加了 `include_downgraded` 开关，复用同一个函数
（§RPT-8 在那里写着「⛔ 不许另写一份切法」，本包照办）。

### 认法（写进判据说明，⛔ 不是一个孤零零的关键词）

**两条彼此独立的路，命中任一即算标明**（「或」不是「且」——要求两样都写会逼出
「海外社区 Reddit 上的海外用户」这种车轱辘话）：

| 认法 | 内容 | 为什么单独成立 |
|---|---|---|
| 一 · 点名平台 | `Reddit` / `Hacker News` / `Product Hunt`（及常见变体） | 中文读者看到这些名字就知道不在国内 |
| 二 · 地域说法 | 海外 / 国外 / 境外 / 外网 / 英文社区 / 英文论坛 / 英文圈 / 国际社区 / 欧美 / 非国内 | 不点平台时的通用说法 |

⛔ **`x` 故意不进平台名表**，两个理由：①X（推特）上大量是中文帖——真稿池里
S23「doubao真有这么好用吗」、S28「apple输入法你再这么烂我真得换doubao了」都是中文，
写「X 上有用户说」读者完全看不出这是海外；②「X」是单字母，拿它做词面匹配会把
「X 轴」「产品 X」全认成命中（词面尺子的经典假绿）。⇒ **引了 X 的条目必须给地域说法。**

⚠️ 认法一认的是**它引的那条证据所在的平台**，不是「文里出现任一海外平台名」：
写「Reddit 上……」却引 Hacker News 的角标照样判红（读者按平台名去找原文会找错地方）。
这条是我写用例时自己先写错了一次、被闸判红才发现的，已单独立一条用例钉住。
