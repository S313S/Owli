# 审稿清单（写完自己过一遍）

> 借自 tyroneross/pyramid-principle 的 pyramid-audit（Apache-2.0），按 Owli 的产物形态改写。

## 结构

1. **答案先行**：执行摘要第一句就是调研问题的答案吗？还是先铺了背景？
2. **每个标题都是一句结论**吗？有没有「XX 分析」「XX 概况」这种话题式标题？
3. 关键发现之间**互不重叠、合起来覆盖问题**吗？有没有两条其实在说同一件事？
4. 每条发现下面的顺序是不是**结论 → 数据 → 解读 → 限定**？有没有把数据堆在前面让读者自己总结？
5. 建议是否每条都能**回指到某一条发现**？有没有凭空冒出来的建议？

## 事实

6. 正文里的每个数字，能在数据表里**原样**找到吗？（不是算出来的、不是约等于的）
7. 每句结论都挂角标了吗？角标号**都在信息源池里**吗？
8. 有没有把词表命中计数说成了百分比或「用户认为」？
9. 只有 C 级证据撑着的话，说满了吗？
10. `SINGLE` 的主张，有没有写成「普遍」「大家都」？

## 语言

11. 正文里还有 `goal-` / `sec-` / `ch-` / 「本节」「本片」吗？（一个都不许有）
12. 有没有节标题照抄了工作稿的目标标题？
13. 有没有「本报告将……」这类过场话？
14. 一段话超过五行了吗？密密麻麻的长段落是这次要改掉的老毛病。

## 交底

15. 附录里写清楚了**样本怎么来的、哪些没采到、词表口径是什么**吗？
16. 覆盖率低的表，正文用它时标注覆盖率了吗？
