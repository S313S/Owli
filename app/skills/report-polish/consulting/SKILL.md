# 调研报告（咨询体）

读者是拿结论去用的人：运营、产品、老板。他们要的是「所以呢」，不是「我们做了什么」。
全篇按下面五节写，一级标题就用 `sections` 里那五个词，一字不改。

## 篇幅预算（用户 2026-09-09 拍：这份稿要短一半）

上一稿全文 2.5 万字符，用户的判语是「像诚实的数据清点单，不像咨询报告」。
**长不是详细，是没归纳。** 你一轮只写一节（或一条发现），所以预算也按节给——
各节都守住，全篇就落在带宽里。**下面数的是字符数**（标点、表格、角标都算）：

**全篇带宽：写手正文 7000–9000 字符**（附录里程序生成的那五块不算）。
下面每一行都是**区间，两头都要守**：⛔ 写不到下限和写过上限一样是不合格。
各行下限加起来比 7000 留了三百字的富余，不是算错了——合并「关键发现」那几片时，
程序会把跨片重复的限定收尾段收掉（实测收掉 171 字符），那一刀落在你交稿之后。

| 这一轮你写的 | 字符区间 | 上一稿实测 |
|---|---|---|
| 执行摘要（整节） | 600–800 | 581（偏短） |
| 关键发现·每条发现（3 条时） | 1100–1300 | — |
| 关键发现·每条发现（4 条时） | 850–1000 | 617 / 695 / 743 / 683（都偏短） |
| 关键发现·每条发现（5 条时） | 700–800 | — |
| 论据与数据（整节） | 600–800 | 549（偏短） |
| 建议 / 对不同读者的含义（整节） | 1300–1500 | 857（偏短） |
| 附录（你写的两小节） | 1500–1800 | 1142（偏短） |

附录里的**缺失清单、各表口径、词表命中参考、代表原声、信息源清单**五块由程序自动接在你后面，
**不算你的预算，你也一个字都不要写**。

⚠️ **为什么补了下限**（2026-09-16 实测）：上一版每一节都只写到上限的 57–74%，
合计 5998 字符，低于全篇下限 7000——而那一轮零打回、零超时，不是被墙钟压的，
是**预算表只给了上限**，写手没有理由往上写。写到六七成再合起来，必然不够。
「短一半」指的是从 2.5 万降到这条带宽，**不是越短越好**：短到读者看不出论证过程，
就又回到「数据清点单」那个判语上去了。
论据与数据这一节要是真没有可列的表，就在这里如实写一句「可列的表都已在关键发现里用过」，
省下的字数**加到关键发现**，别让全篇掉出下限。

**超预算就删「把上面那句换个说法再说一遍」的句子**，不是删内容。三处最容易注水：
同一张表出现两次、两条发现讲同一件事、论据节把关键发现的表重排一遍——这三处上面
各有明写的规矩，守住了篇幅自然就下来了。
**不够下限就补论证**：这张表为什么支持这个结论、这条结论在什么条件下才成立、
相反方向的证据是怎么被排除的——⛔ 不是靠多引一条原声或把表再念一遍凑字数。

⛔ **不许靠删限定句压篇幅。** 「这条结论在什么情况下不成立」「分母是已编码的多少条、
不是全库多少条」「有条数没角标是没进池、不是数据可疑」这一类**一句都不许删**——
它们每一句都是以前某一稿被读者误读之后补上的护栏，读着别扭不等于该删。
要压就压重复，不压限定。

## 执行摘要

先写一段 SCQA，**不超过 150 字**，四句话：

- 背景：这件事的处境是什么（一句）。
- 冲突：出现了什么变化或问题（一句）。
- 问题：于是要回答的问题是什么（就是调研问题本身，一句）。
- **答案：结论是什么**（一句，带量级，带角标）。

然后是 **3–5 条关键发现**，每条一行，格式固定：

```
1. 【A】结论句（主语+判断+量级）[S12][S18]
```

方括号里是这条发现最强证据的等级（A/B/C）。三条以下说明你没读透，六条以上说明你没归纳。
关键发现是全篇最重要的部分——如果读者只看这一块就走了，他也该拿到该拿的东西。

**关键发现只回答题面问的那件事。** 题面问「国内大家对 X 的看法」，关键发现就只写
关于 X 本身的说法。信息源池里两种带栏的源，**待遇不一样**（完整规则见共用规则 §5.7）：

- 带「**旁证·对照实体**」栏的源说的是别家产品，⛔ **不进这 3–5 条**——它们放到
  「论据与数据」里那段「对照与旁证」（§5.7.1）。**写完先数一遍角标**：一条发现的角标里
  对照实体占了大半，这条就挪出去。
- 带「**海外社区**」栏的源 ✅ **可以进**这 3–5 条（用户 2026-09-18 拍板放行，
  ⛔ 别再按旧规矩挡它），**但引用它的那一条必须让读者一眼看出这是海外社区的声音**——
  点名平台（「Hacker News 上的讨论……[S38]」）或点明是海外（「海外开发者社区……[S38]」），
  两样都给最稳。整条的角标**全部**是海外的，还要在那一条里写死适用范围
  （「……本轮国内语料里没有对应说法」）。写法示例与程序判据见 §5.7.2。

**一条发现只讲一件事，两条发现不许讲同一件事。** 任意两条发现的角标有三分之二以上重合，
它们就是一条，合并。 写完先自己过一遍：任意两条，
如果一条的论据能原样搬去支持另一条，那它们本来就是一条，**合并成一条**，别拆成两条凑数。
（实测踩过：第 3 条「差异化叙事推向 AI 办公入口」与第 4 条讲的是同一批微博样本的
两种说法，展开之后两节引同一张表、同一批角标，读者读第二遍时以为自己翻错页了。）

最后固定一句人话置信度提示（共用规则 6.5.2）：

> 本报告结论的把握度为**低 / 中 / 高**，主要因为……

**那个档位不是你定的**：程序按**每条关键发现**自己引的证据算（几个独立出处 / 几个平台 /
最强等级 / 落在编码表哪一格有多少条），整篇取各条的中位档。你那句话里的档位必须写
程序算出来的那一个，对不上当轮打回；「主要因为……」那半句写**哪几条强、哪几条弱**
的人话理由。⛔ 不许写「多数说法只有一个来源所以低」——那句在本项目语料上几乎恒真，
等于每份报告开篇都劝读者别信（共用规则 §6.5.2 里有真稿例句，照那个形状写）。

摘要正文里不许出现 SINGLE / PASS / WEAK / CONFLICT 这些内部口径词，也不许写「253/274」这类方法论读数——那些留给附录。

**把握度判「低」的那几条发现，标题不得大过证据**（共用规则 §6.5.2′，程序当轮核）：
标题里不许出现「普遍 / 大多数 / 主流 / 集体 / 广泛」这类普遍化断言词，
发现行里要交代证据规模或范围（「两篇公众号文章」「同一个帖子下的两条评论」
「本轮样本里」）。判「高」的那几条照旧正常写，不必加限定。

## 关键发现

上面每条发现在这里展开一节，二级标题，顺序固定四步，**一步都不许跳**
（同一张表只在第一次用到它的那条发现里摆，后面写「见第 N 条发现的表」，共用规则 §6）：

1. **行动式标题**（二级标题本身就是那句结论，不是话题）。
   标题之下先按**共用规则 §5.6 的主题段五步**把这个主题交代清楚
   （覆盖面 → 强度 → 2–3 条原声 → 这意味着什么），再往下走第 2 步。
2. **一张数据表**（正式稿不出图，见共用规则 §6）——先写下这张表要说的那句结论，
   写不出就别放表。表下面标一行 `n= · 口径 · 来源角标`。
3. **三到五句解读**：这张表为什么支持上面那个标题。只解读，不搬运——不要把表里每一行
   再用文字念一遍。
4. **反证或限定**：这条结论在什么情况下不成立、哪些证据指向相反方向、样本有什么局限。
   **限定一句话说完**，不要另起「假设与不确定性」小节——那一节全篇只在附录写一次（共用规则 §5.1）。
   这一步只在这条结论真的撑不住时写；撑得住就把话说完整，别为了免责补一句。

**这一节的每条发现都必须是关于调研对象的**（谁在什么场景下夸什么、骂什么），
第 2 步那张主表也得是讲对象的表。平台分布、等级分布、交叉验证分布、时间分布这四张
描述取数过程的表**不许出现在这一节**，「被引」「采集条数」「采集量」这些取数口径词
也不许出现在这一节的正文里——它们的位置在附录（见共用规则 §4.5）。

## 论据与数据

**「对照与旁证」写在这一节**：带「旁证·对照实体」栏的证据如果值得一提，在这里用一段话讲
（共用规则 §5.7.1），⛔ 它们不进关键发现、也不做建议的依据。
⚠️ **带「海外社区」栏的不归这一段管**——它 2026-09-18 起已放行，正文哪一节都进得了，
条件是每次用到都标明是海外社区的声音（§5.7.2）；把它塞回这一段等于把放行又收回去。
「各实体的提及量」那张表**不许拿来比谁的心智占位更高**——
各实体采集的平台数不同，提及量是分配出来的，不是市场出来的（表里的「采集平台数」列与口径写着）。

**只列正文里没有展开过的表**：给你的表里，凡是「关键发现」某一节已经摆出来讲过的，
**这一节一律不许再出现一次**——同一张表在一份稿里出现两次，读者第二次只会跳过。
剩下那些「有用但没进关键发现」的表放在这里，每张带标题（行动式）、`n`、口径、来源角标。
表里的数一个都不许改。

**这一节不是关键发现的表格重排。** 它是「还有哪些数据值得一看」，不是「把上面讲过的
再列一遍」。如果关键发现已经把该讲的表都讲完了，这一节就写一句
「正文之外没有需要单独列出的表」，然后结束——**短是对的，凑长才是错的**。

**态度（谁在夸什么、骂什么、有多少条）的数字，只能引「UGC 逐条编码」那一套表**
（逐条读完再判正负）。词表命中的那张表**不在给你的表里**，程序会把它单独挂在附录作参考——
你拿不到它的数，也不要凭印象写出一个它的数。两套尺子同时进正文，读者只会看到两个
方向相反的数字（用户 2026-09-09 读稿后拍）。

## 建议

按「影响 × 把握度」排序：影响大且把握足的排最前。**建议只从关键发现推**，
⛔ 不从「旁证·对照实体」推（共用规则 §5.7.1）。
⚠️ 带「海外社区」栏的证据 ✅ **推得了建议**（2026-09-18 放行），但那条建议里
**必须让读者看出依据来自海外社区**，写法与程序判据见共用规则 §5.7.2。每条建议两行：

```
1. **建议一句话**（做什么，不是"应该重视什么"）
   依据：回指第 N 条发现；把握度：高/中/低（理由一句）
```

把握度取决于撑着它的那条发现的证据等级和交叉验证结论。**弱证据不撑强建议**——
只有 C 级或全是 SINGLE 撑着的想法，写成「值得进一步验证的方向」，别写成行动建议。

**两道闸，分工不重叠**（共用规则 §6.5.4，程序当轮核）：一道看交叉验证结论（全是孤证
就降级），一道看证据强度（把这条建议所引的角标当成一条发现判把握度，判出「低」的
不许当行动建议）。第二道有两条出路：降级，**或者**留在建议里但把 `把握度：低（理由）`
写进依据行——上面那个格式本来就要求写这一行，照写即可。

降级的那几条**排在这一节的最后**，形态按共用规则 §6.5.4「降级区写成什么样」照做：
要么另起一个 `### 值得进一步验证的方向` 小标题，要么把「值得进一步验证的方向：」
写在条目号和 `**` 之后**紧挨着**（`3. **值得进一步验证的方向：……**`）。
程序只认这两种，写在句子中间不算降级、会被原样打回。

## 附录

「假设与不确定性」写在这一节，全篇只此一处（共用规则 §5.1）。

**你只写两件：①「方法与样本」②「假设与不确定性」。** 共用规则第 7 条那五件事里，
另外三件**由程序生成、自动接在你写完的正文后面，你一个字都不要写**——写了就会重复：

- **缺口清单**：程序按工作稿的缺失清单直接出表，机器 reason 已翻成人话。§RPT-7 起
  它按章型与入库条数分成三张——「哪些没采到」「采到了但没写成段落」「哪些环节没跑完」，
  哪张有行才出哪张。三张都由程序出，你一个字都不要写。
- **各表口径**：程序按每张表自己的 `basis` 字段直接出表。
- **信息源清单**（角标 → 标题 / 链接 / 等级）：程序按证据库直接出表。

这三件本来就是「把现成字段照列一遍」，让你誊抄既费时又会抄错。**样本偏差那四句仍归你写**
（它要按这一轮真采到的平台挑，不是照列）。

**⛔ 还有一张表也由程序接在附录：代表原声表**（用户 2026-09-11 拍）。
它跟上面三件不一样，**这张表的数据仍然投给你**——因为共用规则 §5.6 步骤 4 要你在
每个主题段引 2–3 条原声写成引用块，那是整份稿里唯一让读者听见真人的地方。

⇒ **「表」和「引用块」是两个产物，别混**：
- **引用块**（`> 原文…` 那种）仍归你写在正文，照 §5.6 步骤 4 的格式写。
  ⚠️ 但**某一格没有可引的原话就是真的没有**——表已按等级筛过（A/B/C，D 不进），
  照 §5.6 那条写一句「本轮这一格没有可引的原声」；有原话、等级是 C 的**照引并标「等级 C」**，
  ⛔ 不许写「未截取到评论正文」这类与池子相反的话，也不许去够 D 级或帖子标题凑；
- **整张表**由程序照列挂在附录，**⛔ 你不许把它摆进正文的任何一节**——
  摆了就是「同一张表出现两次」，读者第二次只会跳过。
