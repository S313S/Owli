# 竞品对比稿

读者要在几个产品之间做判断。他们要的是**一张能横着读的表**，加上表里每一格的依据。
一级标题就用 `sections` 里那六个词。

维度沿用竞品画像章的结尾字段：**产品定位 / 能力侧重 / 国内用户口碑 / 价格与门槛 / 渠道与生态**。
`entity_dimension` 表里出现了别的维度就一并纳入，没证据的维度整列去掉，不许留空列充数。

## 执行摘要

SCQA 一段（≤150 字），答案那句必须是**一个可比较的判断**：谁在什么维度上占优、
差距有多大、这个判断的证据有多硬。

然后 3–5 条关键发现，格式同咨询体：`1. 【A】结论句 [S12]`。
对比稿的发现要落在**实体之间的差异**上，不是某个实体自己的特点。

最后固定一句人话置信度提示（共用规则 6.5.2）：

> 本报告结论的把握度为**低 / 中 / 高**，主要因为……

摘要正文里不许出现 SINGLE / PASS / WEAK / CONFLICT 这些内部口径词，也不许写「253/274」这类方法论读数——那些留给附录。

## 对比总览

**一张实体 × 维度矩阵**，直接用 `entity_dimension` 表。格里是证据条数，
每格后面带该格的角标。表下标一行 `n= · 口径 · 来源角标`。

矩阵下面写三到五句：哪些格子密（说明这个维度上讨论多）、哪些格子空（说明没采到，
不等于这个产品在这个维度上差）。**空格子只能解读成「本轮没采到」，不能解读成「不行」**——
这是对比稿最容易出的错。

同时看 `entity_mentions` 表：提及量差距大时，要点明这可能是采集偏差而非真实热度差，
除非各平台的采集量本身是均衡的（查 `platform_mix`）。

## 逐维度对比

每个维度一节，二级标题是**一句带比较的结论**（行动式标题），例如
「在回答质量上，A 的抱怨集中在准确性、B 集中在回避提问」。每节：

1. 该维度下各实体的说法，一实体一小段，每段至少一个角标。
2. **一句横向对比**：这个维度上谁更强、依据是什么。
3. 证据不够就直说：「本维度 A 只有 2 条 C 级证据，不足以与 B 比较」。

不许在任何一个维度上给没有证据的实体编说法。

## 谁强在哪

**一张总表**，一行一个实体：

| 实体 | 强在哪 | 弱在哪 | 证据强度 | 角标 |
|---|---|---|---|---|

「证据强度」写这个实体名下被引证据的最高等级与条数（查 `grade_mix` 与 `entity_mentions`）。
证据强度是 C 或只有单源的，「强在哪 / 弱在哪」两栏必须带「（单源，待核实）」字样。

表下面用一句话回答读者真正的问题：**如果只能选一个，什么场景选谁。** 如果证据不足以回答，
就明说不足以回答，不要含糊过去。

## 建议

同咨询体：按「影响 × 把握度」排序，每条回指某条发现，弱证据不撑强建议。
对比稿的建议要落在**选择或应对**上（选哪个、防哪个、补哪块），不是泛泛的「持续关注」。

## 附录

按共用规则第 7 条四件事写。对比稿额外交底一件：**各实体的采集量是否均衡**，
不均衡就写明白，免得读者把采集偏差当成市场事实。
